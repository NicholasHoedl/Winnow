# ADR-0025: One Food Search, With Generic Foods Built In

**Status:** Accepted
**Date:** 2026-09-10
**Amends:** ADR-0005 (its alternatives: the USDA database was rejected as an API; its
public-domain dataset is bundled)

## Context

The "Log food" dialog offered three ways to fill one form: a picker over the library
(instant, substring on name), a barcode button, and a separate "Search the food database"
panel that asked Open Food Facts, listed products, and imported one into the form. The
hand-entry fields sat under all of it.

The user's report was that the database "does not seem to be very high quality, or
otherwise the lookup is too finicky to make it useful". Both, and for one reason: Open
Food Facts is a catalogue of packaged products, and most of what a home cook logs is not
one. Queried live for "banana", it answered with supermarket SKUs from two countries, two
of eight without calories, brand-prefixed names, and everything per 100 g with a hint to
set the servings yourself. Sorted by popularity, which the service supports, it answered
with a cocoa powder, banana chips and a soy drink. There is no canonical banana in it, and
no "1 medium".

ADR-0005 had considered USDA FoodData Central and rejected it: its API needs a key, and its
coverage of barcoded retail products is weak. Both remain true. Neither applies to bundling
its generic-foods dataset. FoodData Central is public domain (CC0), and its SR Legacy
release is about 7,800 generic foods with per-100 g nutrients and household measures — "1
medium (7" to 7-7/8" long)", "1 cup, sliced" — which is exactly the data the packaged
catalogue lacks.

## Decision

**One search bar, three groups.** The dialog has a single "Find a food" input. Results
arrive in the order they are worth reading: **Your library**, instant and ranked by what
you log; **Reference foods**, from the bundled dataset; **Packaged products**, from Open
Food Facts, after a longer pause and only from three letters. "Create '…'" is the last
row. Picking anything fills the same form, with "Save as a new food" on for a reference or
packaged pick; the separate import step is gone. The food manager uses the same component
without the library group, since it is the library.

**The reference foods ship with the app.** `scripts/build-food-reference.ts` trims USDA's
SR Legacy JSON to the ten figures the food model holds plus each food's portions, into one
generated file of about 1.2 MB, loaded once per server process and searched in memory.
No migration, no key, no network, no dependency, and the primary path is testable offline
— ADR-0005's own principle, that a self-hosted app must not depend on the network, applied
to the path that matters most. USDA asks to be named as the source; the dialog does.

**Searching is a Server Action, not a client index.** A megabyte is fine in a server bundle
and not something to send to a phone for every visit to `/meals`; the in-memory index
answers in milliseconds, which is instant enough.

**The scorer prefers the plain food.** Every query token must land, on the head noun or as
a prefix of a name token; a hit on the head noun counts more; adjacent tokens in order
count more; and a standing bias moves the plain form of a food ("raw", "cooked", "all
commercial varieties") up and a preparation, product or brand ("breaded", "powder",
"CHOBANI") down. That bias is what puts "Chicken, broilers or fryers, breast, meat only,
cooked, roasted" above the shorter "Chicken breast tenders, breaded" — the case a
length-only tiebreak got wrong.

**Portions are scaled at pick time.** A reference food is per 100 g; the form takes its
usual portion (a "medium" if it has one, else USDA's first measure, else 100 g), scaled by
a pure function, and offers the rest in a Portion select that rewrites the figures. The food
model is unchanged: a library food still has one serving label, as an import does.

**Quick add falls through.** "banana x2" with no banana in the library asks the reference
foods, logs the best match at its usual portion, and saves it to the library so the next
time is answered in the browser. It refuses with the bar's own "Couldn't parse that"
wording when the name is not clearly one food — the best match must be named by the query,
on the head noun or the word after a group head ("Fish, salmon") — and hands the text back.

**Open Food Facts stays, asked for better.** English names requested, hits without calories
dropped, duplicate names collapsed, capped at six, relevance order kept. Barcodes are still
its job; a product in your hand has no better source.

## Consequences

- **A 1.2 MB generated file lives in the repository.** Regenerated by the script from a
  fresh download; the release it was built from is named in the file. SR Legacy is exactly
  that, legacy: USDA stopped revising it in 2018 in favour of Foundation Foods, which is
  smaller and per-nutrient richer. Generic foods do not change, so this is a feature for
  a bundled dataset rather than a debt; a later tranche can add Foundation or FNDDS the
  same way.
- **Three Server Actions may be in flight for one keystroke** — reference, packaged, and
  none for the library. Each group renders on its own; a slow or dead Open Food Facts
  leaves its group saying so under the two that answered.
- **The specs drive the primary path offline for the first time.** `meals-food-search.spec`
  types "banana", picks the reference banana, changes its portion, logs it, and finds it
  under Your library. The Open Food Facts assertions stay offline-safe as before.
- **The scorer's word lists are a heuristic**, checked against a dozen everyday queries and
  pinned by tests; a food it ranks wrongly is one pick further down, and the Create row is
  always there.
- **US-centric data**, matching the app's imperial-by-decision figures.

## Alternatives considered

- **USDA's API live.** A signup key in the environment, a network path on the primary
  route, a rate limit of a thousand requests an hour, and nothing gained for generic foods
  that the bundled file does not give faster.
- **Search only the library and Open Food Facts, but rank OFF better.** Tried live; the
  ranking is not the problem, the catalogue is. A banana is not a packaged product.
- **Ship the dataset to the browser.** Truly instant, at the cost of a megabyte per visit
  to the page on a phone; the Server Action answers within a keystroke.
- **Bundle Foundation Foods or FNDDS instead.** Foundation is a few hundred foods; FNDDS is
  "as eaten" dishes with portions, ~5,400 of them, and a good second dataset. SR Legacy
  has the raw ingredients and the household measures, which is the first need.
